# 文档总览

本目录存放本项目的全部交付文档。本项目是一颗面向大模型推理的数据流架构端侧 ASIC：芯片以独立 PCIe 设备的形式接入 host，片内由多个 Tile 组成二维 Mesh。

本 README 是**交付清单的权威来源**：要交付哪些文档（SPEC 与手册），每份给谁看，成熟度怎么划分。进度和计划见路线图 issue。

---

## 1. 文档分类与目录

| 类别 | 编号前缀 | 目录 | 性质 |
|---|---|---|---|
| 总体文档 | `DOC` | `general/` | 需求、分析、约定、计划 |
| 规格 | `SPEC` | `spec/` | **规范性**：定义硬件"必须怎样"，gem5 模型、驱动、编译器（以及将来的 RTL）都以此为准 |
| 手册 | `MAN` | `manual/` | **使用性**：面向具体读者讲"怎么用"，引用 SPEC，不重复定义 |
| 决策记录 | `ADR` | `adr/` | 每个重要的架构取舍记一条，写明背景、备选方案和结论 |

两条规则：

1. SPEC 与手册冲突时，以 SPEC 为准。手册只引用 SPEC 章节，不复述定义。
2. 寄存器、架构参数、指令编码不在文档里手写，以机器可读的单一真源为准；当前源已删除，待重建，见 [§4](#4-单一真源)。

## 3. 版本与状态

| 版本 | 状态 | 含义 | 下游可以做什么 |
|---|---|---|---|
| v0.1 – v0.4 | 草稿（Draft） | 内部编写中，随时可能大改 | 不建议依赖 |
| v0.5 | 评审（Review） | 结构与主要机制已确定，参数可能调整 | 开始建模，设计软件架构 |
| v0.8 | 稳定（Stable） | 接口与语义已确定，只做小修 | 开始实现驱动、编译器后端 |
| v1.0 | 冻结（Frozen） | 之后的修改须走变更申请（ECR），并通知所有读者团队 | 正式实现 |

每次升到 v0.5、v0.8、v1.0 时，须由 §2 中标 ● 的读者团队完成 review 并确认。

## 5. 决策状态

### 5.1 已确定（2026-10-18；前四项随 Device 侧架构图 v0 确认）

| 事项 | 影响的文档 | 结论 |
|---|---|---|
| Tile 控制方式 | SPEC-200 / 230 / 330，MAN-020 | 管理 Tile 集中派发张量级指令（M100 式）；每个功能单元一条指令队列、顺序执行；单元之间、Tile 之间用同步计数器 |
| 初版参数起点 | 全部 Tile 级 SPEC | 6×4 Mesh：第 0 列 4 个 Memory Tile，中间 4×4 个 Compute Tile，第 5 列 PCIe / 管理 / 预留；每个 Compute Tile 8×64×4 点积阵列、2 MB SRAM、1 GHz。数值以单一真源为准（待重建） |
| NoC 建模方式 | SPEC-120，MAN-060 | 自研轻量 Mesh 模型，粒度为 DMA 传输，支持多播；Garnet 只做交叉验证 |
| 基准模型 | DOC-002 | LLaMA2-7B 为主，Llama-3.2-1B 为辅 |
| gem5 全系统平台的 host ISA（2026-10-25） | MAN-050，SPEC-310 / 400 | AArch64，`VExpress_GEM5_*` 平台，先裸机后 Linux；x86 暂不做 |
| SRAM 操作数寻址 | SPEC-110 / 230，MAN-020 | Tile 相对寻址：指令中落在本地窗口（`address_map.local_sram_base`）内的地址指执行该指令的 Tile 的 SRAM，同一条指令可多播给多个 Tile；跨 Tile 访问仍用全局窗口。越出 SRAM 容量的程序由管理 Tile 在派发前拒绝 |
