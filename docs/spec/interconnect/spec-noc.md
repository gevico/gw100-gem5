## 1. 范围与参数归属

本文定义 6×4 Mesh 的报文、有限资源、接口、完成和分层计时契约。
G0 交付共享定义、静态检查及参考预算。G1 验收路由器和 NI，G2 接入完整
Mesh 与现有系统，G3 验收生命周期、周期实测与整机性能。

本轮采用已确认的分层预算、周期精确性能评估及 64 B 含报头三项决策。
1 µs 为明确流量条件下的端到端性能目标。目标服务、持续竞争、源端等待和
接收方反压分别观测，硬上界需要独立的流量约束与证明。

`spec-src/noc/gw100-noc.json` 拥有本子系统参数、编码、覆盖项和关口状态。
`tools/noc_spec.py` 生成 C、C++、Python 定义、覆盖矩阵和预算表。
新增数字均为 GW100 参考微架构选择或其推算，依据逐项保存在档案中。
地址窗口、权限矩阵、内存参数和 PCIe 时钟分别引用其现有真源。

当前运行配置的设备内存通路使用 32 B、1 GHz 临时适配器。G0 的 512 位
Mesh 与 128 B 源 CDC 由后续接入关口落地。当前原生 FR-FCFS 控制器的
最坏服务时间保持未证明状态。覆盖矩阵、预算与复现记录分别保存于本文附录。
[覆盖矩阵](spec-noc/coverage.md)、[预算](spec-noc/budget.md)、[验证记录](spec-noc/verification.md)

## 2. 拓扑、时钟和有限资源

### 2.1 坐标与身份

路由节点编号为 `NodeId = y×6+x`，坐标满足 `0≤x<6、0≤y<4`。
地址窗口编号为 `WindowId = y×8+x`，窗口大小为 16 MiB。
C 使用独立结构体，C++ 和 Python 使用独立枚举表示三个编号类型。
窗口转换必须经坐标完成。

| 来源 | SourceId | 坐标 | 数据子请求槽 |
|---|---|---|---|
| 管理 CPU | 0 | (5,1) | 16 |
| HDMA | 1 | (5,0) | 64 |
| BAR2 | 2 | (5,0) | 16 |
| Compute 0–15 | 3–18 | (1+i%4,i/4)，i 取整数商 | 各 16 |
| Memory 控制 0–3 | 19–22 | (0,i) | 0 |

四个 Memory Tile 位于左列，Compute 位于中间四列。节点 17、23 保留路由器，
本地 NI 省略。PCIe 的两个来源共享物理 NI，来源事务账本独立。
共 24 个路由器、22 个有效 NI、18 个物理请求者 NI、76 条有向邻接链路，
包括本地端口后有 98 个有效输入及 98 个有效输出，均为拓扑推算。

来源编号由物理入口绑定。Memory 的控制来源只产生硬件控制消息。
管理控制生产者使用来源 0，PCIe NI 的硬件控制生产者使用来源 1。
软件提供地址、长度和数据，线上身份、发送节点和准入标志由 NI 生成。

### 2.2 链路与路由器

| 项 | 首版参考值 |
|---|---|
| 核心时钟与 tick | 1 GHz、1 ps |
| 物理链路 | 每方向每周期一个 64 B flit，双向独立 |
| 路由 | 确定性 XY，先 X 后 Y |
| 交换 | 完整包存储转发 |
| 路由与分配 | 两级流水，每级一个核心周期 |
| NI 封装与接收 | 每端各两级核心流水，属于 G0 参考选择 |
| VN / VC | REQ=0、RSP=1、COMMAND=2、CONTROL=3，每 VN 一个 VC |
| 输入 | 每有效物理输入、每 VC 四个 flit |
| 输出 | 每有效物理输出一个 flit 寄存器 |
| 信用 | 每 VC 以 flit 计，完整包信用原子预留，释放后一个核心周期返回 |
| 仲裁 | 完整包且信用足够者按本路由器到达次序优先，同龄冲突轮询 |

报文全部到齐才进入路由和分配。一次授予持续整个包，最多两拍。
每输入和输出每周期最多传一个 flit。两级控制流水可与已授予包的尾拍重叠，
持续流的峰值由一拍一个 flit 限制。输出寄存器的发送与接收链路占用计入
每 flit 的一周期传输，首末本地链路也采用同样的宽度和计时。

授予前同时检查输入、输出及该 VC 的下游未预留信用。预留值、已用值和
可用值分别计数，每个存储 flit 释放一次。分配失败保留完整包，继续仲裁其他可发送
候选。每输入对其可发送输出的同龄选择也采用轮询。64 位到达序号在溢出前
关闭该路由器的新接收，待已有包排空后重建序号。

NI 接收采用 128 B 固定槽，向 NI 的每个包预留两个存储 flit 信用，
短包的尾部槽空间也计入预留。每 VN 八槽对应 16 个信用，计数器使用五位。
包被消费后归还两个信用，每周期返回一个，内部空槽字节由 NI 补零。
短包线上仍传一个 flit。路由器之间按实际包 flit 数预留四深度输入信用。

RSP 与 CONTROL 拥有独立输入缓冲及 NI 接收空间。NI 接收事务前预留完整
响应和元数据，收到响应后能够搬入该事务预留的响应槽。目标接收与返回资源
必须共同满足准入条件。四个 VN 的 XY 通道依赖图分别无环，应用长期不接收
造成的停顿另记。G1 继续验证 NI 和目标适配器构成的协议依赖及公平性。

### 2.3 NI、CDC 与成本口径

| 资源 | 首版参考值 |
|---|---|
| 数据子请求槽 | 合计 352，以 64 B 子请求计，包含返回反压占用 |
| 管理指令槽 | 8 |
| 控制事务槽 | 每有效 NI 4，共 88 |
| 总事务槽 | 448，含 352 数据、8 指令和 88 控制 |
| 每事务存储 | 请求 128 B、响应 128 B、元数据 32 B |
| NI 接收 | 每 VN 八个完整包槽，每槽 128 B，另有 16 B 描述符 |
| 父事务 | 引用 `memory.SOURCE_LIMIT=16`，每逻辑数据来源各 16 个，描述符 64 B |
| 来源状态 | 每 SourceId 32 B，含 tag、顺序号和在途状态 |
| NI 控制 | 每物理 NI 256 B，含 64 B 错误快照及 16 个 64 位计数器 |
| Compute NI 区间 | 八个执行区间及八个管理 SRAM 开放区间，每记录 81 bit |
| 保护镜像 | 每请求者物理 NI 四份，每份 64 B，共 4608 B |
| 源端 CDC | PCIe、管理各请求/响应 FIFO，128 B 完整包一拍，八拍深，两级指针同步 |
| DDR 边界 | 每通道请求/响应各 32 B×八拍、两级同步，由内存档案拥有 |

源端 CDC 一拍承载一个完整包，短包也占一个槽。其四个 FIFO 共 4096 B
数据存储。DDR 第一拍承载请求或响应头，写请求与读响应另传数据拍，
64 B 数据对应两拍数据，连头共三拍。DDR 的 FIFO 数据、描述符和指针
成本独立列入预算，16 B 描述符为参考逻辑预算，由 Memory Tile 接入时核验。

32 B 事务元数据含 transaction16、expected24、received24、rejected24、
faulted24、parent_slot8、state8、内部 epoch64 和 issue_order64，合计 256 bit。
请求槽保留地址、长度、来源和原始报头。16 B 路由描述符保存到达序号和包
位置等调度状态，报头保存在输入数据中。最短一拍包决定描述符数量，
每 VC 四个输入 flit 对应四个描述符。

预算逐项核算 FIFO、输出寄存器、描述符、流水元数据、NI 队列、事务存储、
父事务、状态、权限镜像、CDC 指针和链路旁带。每方向旁带包含
valid/head/tail/VN 共五位及信用 valid/VC 共三位。布线位数按两条方向计，
时钟复位树、线长、ECC、门面积和功耗由物理实现阶段核验。

## 3. 线上报文

### 3.1 报头和载荷

报头固定 16 B，小端布局从最低位依次排列，完整 LSB 表由覆盖矩阵生成。

| 字段 | 位数 | 语义 |
|---|---|---|
| opcode / VN / flags | 4 / 2 / 2 | 类别及 MULTICAST=1、BYTE_ENABLE=2 |
| initiator / destination / sender | 5 / 5 / 5 | 原发起者、当前目的节点、发送节点 |
| admitted | 1 | 已准入父事务的报文为 1，由 NI 产生 |
| transaction | 16 | 发起者账本内的子请求标识 |
| address | 40 | 原始 DPA，数据多播时为 SRAM 公共偏移，CONTROL 时为子类型 |
| length | 8 | 数据字节数，最多 64，排除报头、字节使能和填充 |
| destinations | 24 | 多播目的 NodeId 位图，单播为零 |
| status / reserved | 8 / 8 | 请求为 OK，保留位恒零 |

| 请求 | 编码 | VN | 响应编码 | 请求载荷 | 成功响应载荷 |
|---|---|---|---|---|---|
| READ | 0 | REQ | 8 | 无，length 为读取长度 | length 字节数据 |
| WRITE | 1 | REQ | 9 | 8 B 字节使能，后接 length 字节数据 | 无 |
| COMMAND | 2 | COMMAND | 10 | 管理来源发出的 1–64 B 不透明指令 | 无 |
| EVENT | 3 | CONTROL | 11 | Compute 发往管理 Tile 的 4 B 事件写 | 无 |
| CONTROL | 4 | CONTROL | 12 | 固定 64 B 控制载荷 | 无 |

全部响应走 RSP。除成功 READ 响应外，响应 length 为零。
REJECT=1、FAULT=2 的响应无数据。响应回显原 transaction、initiator 及 address，
sender 为实际目的 NI，destination 为发起者物理节点。多播叶子返回独立单播
响应，清除多播标志和目的掩码。

READ、WRITE 及成功 READ 响应的地址和长度落在同一个 64 B burst。
写包必须携带八字节字节使能，第 i 位对应当前对齐 burst 的第 i 个字节，
范围外位恒零。使能可全零，结果为无数据效果的正常写完成。
剩余 flit 字节补零，填充占用链路。

完整读响应为 16+64=80 B，完整写为 16+8+64=88 B，均占两拍。
读请求和无数据响应各一拍。写载荷≤40 B 或普通消息载荷≤48 B 时占一拍，
超过后占两拍。G1 的事务日志同时记录有效字节、真实包字节和填充字节。

### 3.2 控制协议

| address 子类型 | 值 | 来源与处理 |
|---|---|---|
| PROTECTION_SYNC | 0 | Memory 控制来源 19–22 向请求者 NI 发布本 Tile 的 64 B 快照 |
| QUIESCE | 1 | 管理控制生产者关闭指定来源或目标，等待排空后响应 |
| RESUME | 2 | 管理控制生产者在状态允许时恢复指定来源或目标 |
| ERROR_REPORT | 3 | 硬件报告者向管理 NI 交付 64 B 诊断快照 |

保护快照依次含 tile8、version32、locked1、test_mask2、ready_mask2，
随后四条区域记录，每条为 base40、exclusive_limit40、enabled1，余下
143 bit 为零。version 从 1 开始，同 Tile 单调增加，溢出前停止更新并报错。
测试与就绪位对应 Tile 内两通道，范围以全局 DPA 表示。启用区域以 4 KiB
对齐且落在安装容量内。内部仿真复位代次只保留在对象账本。

QUIESCE、RESUME 的载荷最低 24 bit 为 SourceId 位图，随后八位为 mode。
mode 位 0 控制来源准入，位 1 控制目标准入，其余为零。来源隔离时位图非空，
只作用于接收 NI 绑定的来源。剩余 480 bit 为零。控制消息按目的 NI 串行提交，
RESUME 等待先前隔离终态。ERROR_REPORT 的 64 B 由报告者的有界诊断快照
提供，RAS 汇聚器按报告者类型解码，NoC 保留原始字节。

快照和控制消息使用同样的包、信用、竞争和回包路径。其接收服务持续开放，
数据隔离时仍可处理控制和已有事务的响应。格式、来源或版本检查失败返回
REJECT，未知数据效果使用 FAULT。

## 4. 地址、权限与保护传播

源 NI 在产生任何数据效果前预检完整父请求，检查范围、安装容量、来源权限、
全部分片和全部多播目的。跨越保留地址或受保护区域使整个父请求 REJECT。
合法父请求在 64 B 与 256 B 边界拆分，分片可分批取得有限事务槽。
完整预检不能依赖目标对象的零时间私有状态读取。

DRAM 地址保留 40 位原始 DPA，通道取 DPA[10:8]，Memory Tile 行号为
通道号右移一位。NI 只选择目标，通道位压缩由 DRAMInterface 完成一次。
32 GiB 之外的设备内存保留，Tile 本地别名不能进入 NoC。
Memory Tile 控制区位于窗口内 0x800000–0x802fff。

源权限沿用地址规格。管理 CPU 可访问 DRAM、Compute SRAM/寄存器及
Memory 寄存器。HDMA 可访问 DRAM 和 Compute SRAM。BAR2 只访问 DRAM。
Compute 的 DRAM 父请求须完整落入一个 X 区间，管理 SRAM 的全部分片须被
固件开放区间覆盖。两种区间各八项，以全局 DPA 的两个 40 位端点和使能位表示。
Compute 的同步寄存器访问仅限其他 Tile 声明的写入白名单，白名单由目标
接口描述符提供，空白名单拒绝全部此类访问。Compute 内部设计拥有具体偏移。

管理事件只接受自然对齐的四字节写，目标继续限制可写事件位。
管理 Tile 的本地 CPU 访问其 SRAM 和事件寄存器走本地路径。
寄存器窗口译码成功之后仍由目标检查实际寄存器、宽度和写权限。

每个 Memory Tile 向 18 个请求者物理 NI 同步自己的四项保护区域和状态。
同一物理 PCIe NI 的 HDMA、BAR2 共用镜像。NI 原子安装完整快照后返回确认，
源端收齐匹配版本的全部 OK，Memory Tile 的 ENABLE 才能完成。
任一确认 REJECT 或 FAULT 时保持未开放，记录失败节点，按状态恢复或失败。
目标始终独立检查权限。FLR、D3hot 保留已锁定快照，全设备复位清除。

NoC 释放后管理 CPU 可访问 Memory 控制寄存器，镜像未安装或普通数据未就绪
时限制普通数据准入。管理自检由对应通道 test_mask 及目标实际训练状态共同
许可。已准入父请求执行期间配置保持稳定，先停止新父请求、排空旧请求后
更新可变状态。保护表锁定之后按内存规格保持到设备复位。

## 5. 事务、顺序和多播

### 5.1 完成与数据可见性

父请求在 ACCEPT 前可被反压。接受后恰好完成一次。子请求消耗来源的 64 B
数据槽，响应被上游接受后释放槽及 transaction。查找键为 initiator、
transaction、预期目标 sender，并检查响应 opcode、地址、长度和状态。
目的位图防止重复完成。错误匹配和重复终态报告协议错误。

同一 SourceId 的数据、指令和硬件控制共用 tag 分配器，各类保留自己的
事务槽。父描述符保留范围与生产者句柄，写数据由生产者的有限缓冲保持。
NI 取得某分片的请求与响应槽后才接收该片数据，使用有背压的分片握手，
生产者在确认之前保留数据。生产者可逐片接受响应并更新自己的有界父缓冲，
该片的槽和 tag 随后释放，父描述符保留到全部片收尾。指令和控制各为单包
事务，直接使用其事务存储。

同来源对重叠 burst 的访问串行执行，包含部分写 RMW。目标对每个地址保持
唯一写入序，自然对齐的 1、2、4、8 B 访问不可撕裂。
普通写完成表示目标可见，之后合法读可由控制器转发取得新值。
fence 等待本来源此前全部父事务完成。媒体排空额外等待实际写传输和恢复，
由 Memory Tile 提供独立完成接口。

预检阶段的 REJECT 保证该父请求未产生数据效果。执行中的某片 REJECT 时
停止未发分片，等待所有在途片结束。父结果包含 partial 标志、完成字节数及
逐片返回，生产者据此报告已知部分效果。多播同时返回逐目的位图。
该汇总 REJECT 保留已完成片的效果。任何片的效果未知时汇总为 FAULT。
硬件故障导致 FAULT 时效果未知，后续仍可能生效，按地址和复位规格进入致命
错误恢复。报头损坏到无法可靠匹配时，通过 NI 致命故障接口通知控制平面。

### 5.2 分支多播

WRITE 与 COMMAND 可指定 16 个 Compute 的任意非空目的集合。多播 WRITE
使用共同 SRAM 偏移，展开每个目标的全局地址并完成整请求预检。
COMMAND 只由管理来源产生，载荷作为不透明字节传送，确认表示接收完成。
指令执行完成和跨包指令组合由 Compute/ISA 契约拥有。

每路由器按下一跳将目的位图划分为互斥子集，本地目的形成独立分支。
每个分支重写 destination 为子集最小 NodeId，并保留该分支的目的掩码。
输入包在全部分支发送完成前保留，每输入每周期只服务一个输出。
发送分支只预留当前输出的完整包信用，其他输出独立仲裁。逐边、逐副本
记录 flit 和信用占用。CONTROL 多播另外允许管理及 PCIe 两个请求者节点。

发起 NI 预留 expected、received、rejected、faulted 四个位图，收齐所有
目的地终态后才返回一个父结果。优先级为任意 FAULT、存在 REJECT、全部 OK。
部分 REJECT 包含逐目标完成信息，已完成目标的效果保留。父事务终态及
位图交给上游适配器，线上叶子响应保持独立。

## 6. 生命周期、故障与接入接口

| 边界 | 契约 |
|---|---|
| CRC 释放 | 核心时钟稳定且 NOC 复位释放后，路由器与 NI 开始工作，默认路由可达全部 Memory 寄存器 |
| NI 隔离 | 关闭新父事务，已准入父事务继续分片并收尾，目标拒绝尚未执行的请求 |
| 排空 | 等待父事务、所有分片、分支副本、目标效果、响应和上游返回反压收尾 |
| 隔离成功 | 所有有关事务为 OK/REJECT，无旧写继续生效，再发 ACK |
| 隔离失败 | FAULT 或隔离期限耗尽，记录 FAIL，保持隔离，交由设备完全复位恢复 |
| FLR | 保留 Mesh、内存及保护配置，只隔离 PCIe 来源 1、2 并退休旧事务 |
| 全设备复位 | 全部 Mesh 端点共同撤销在途工作，内部对象代次更新，事务和镜像重新建立 |
| D3hot / D0 | PCIe 业务关闭，排空相关事务后调用内存自刷新，恢复等待完成再开放业务 |

已被源 NI 接受的父事务在关闭新准入后继续使用原许可。target 尚未接受的
请求可 REJECT，已交给 target 的请求等待真实结果。隔离响应返回生产者并
进入其预留返回槽后，上游先关闭业务并提交取消接收，NI 才能消费旧返回。
普通运行期持续返回反压包含在排空中。成功隔离要求两方完成此握手，
单纯删除仿真回调无法构成隔离成功。

`clock.tile_txn_timeout=5 µs` 从隔离过程中的 TARGET_ACCEPT 计到
TARGET_COMPLETE，适用于已交给 Compute 服务替身的请求。
`clock.tile_iso_timeout=50 µs` 从隔离请求计到 ACK/FAIL，包含控制传播、
目标排空、NoC 返回和 CDC。二者为参考策略，后续压力矩阵核验适用流量。
持续拥塞或接收阻塞耗尽期限时进入隔离失败，FAULT 保留效果未知语义。

| 接口 | 必要输入与结果 |
|---|---|
| 来源提交 | 硬件来源、读写/指令、DPA 或 SRAM 偏移、长度、字节使能、可选 Compute 掩码，返回接受或 retry |
| 来源 fence | 本地屏障操作等待本来源此前全部父事务完成，再接受其后的操作 |
| 来源完成 | 子片句柄、状态和数据，接受后释放子槽。父终态含 partial、完成字节数及逐目标位图 |
| 目标提交 | 已检查的子请求、真实线上身份，目标返回接受或反压 |
| 目标完成 | 可见完成或 FAULT，媒体排空使用独立调用 |
| 配置控制 | 有界控制队列，快照原子安装、隔离/恢复及错误报告使用 CONTROL 协议 |
| Compute 替身 | 可配置读写流量、2 MiB SRAM 范围、服务等待、返回背压及故障注入 |

每个时钟沿内先处理全局复位、隔离与时钟门控，再处理已有完成、信用归还、
新准入和仲裁。释放产生的信用在约定返回边沿可见，同一事务只能出现一次
终态。内部对象代次用于屏蔽已共同复位的回调，响应匹配只使用真实线上字段。
G1 的 trace 和目标替身遵循相同事件边界，计算单元内部行为单独定义。

## 7. 分层时延与吞吐预算

### 7.1 计时边界

| 事件 | 定义 |
|---|---|
| OFFER | 上游首次给出完整父请求，开始源端等待统计 |
| ACCEPT | 源 NI 接受父请求及其描述符，预检与分片等待从此计入 |
| REQ_INJECT | 请求首 flit 开始向本地路由器传输 |
| REQ_EJECT | 请求尾 flit 完整进入目标 NI |
| TARGET_ACCEPT | 目标服务接受子请求，开始目标服务计时 |
| TARGET_COMPLETE | 目标产生可见结果，结束目标服务计时 |
| RSP_INJECT | 响应首 flit 开始向本地路由器传输 |
| RSP_EJECT | 响应尾 flit 完整回到源 NI |
| COMPLETE | 上游接受父请求的全部结果，释放父事务和子请求身份 |

统计单独记录 OFFER→ACCEPT、源 CDC、请求 NI 流水和传输、目标排队、
目标服务、响应 NI 流水和传输、返回 CDC、上游接收等待。
REQ/RSP 的 INJECT→EJECT 包括其本地输入输出链路。
REQ_EJECT→TARGET_ACCEPT 分成目标 NI 流水、DDR 请求 CDC 和目标队列。
TARGET_COMPLETE→RSP_INJECT 分成 DDR 响应 CDC、目标响应等待及 NI 发送流水。
NI 流水和各 CDC 单独保存起止边沿，分层合计采用互不重叠的子段。
服务从 TARGET_ACCEPT 独立计算，Mesh 与 NI 的参考合计包含四段 NI 流水。
排空和错误恢复计时采用对应控制请求的边界。

### 7.2 无竞争公式

令 H 为相邻路由器跳数，Fq、Fp 为请求与响应 flit 数，P 为核心周期。
单方向从源核心侧完整包可用到目标 NI 接收完成的参考时延为

```
Tmesh_one(F,H) = [2×N + (H+1)×R + (H+2)×F×L]×P
Tmesh_round = [4×N + 2×(H+1)×R + (H+2)×(Fq+Fp)×L]×P
N=2，R=2，L=1，P=1000 ps
```

公式包含每方向两个 NI 流水、H+1 个路由器、H 条相邻链路及两条本地链路。
完整 64 B 读写的 Fq+Fp=3，零跳往返 18 ns，八跳为 74 ns，均为推算。
CONTROL VN 的四字节 EVENT 往返为 `(16+6H) ns`。固定 64 B CONTROL 为两拍
请求与一拍响应，使用读写同样的往返公式。

CDC 以写端首拍在可用时刻之后的首个边沿开始。B 拍全部写入，经过读端
首个严格后继边沿及 S 级指针同步后读取 B 拍，参考相位包络为

```
Tcdc_bound = (B+1)×Psrc + (B+S+1)×Pdst
```

该公式独立列出源边沿等待、写入、目标边沿等待、同步与读取。持续背压另计。
分析器另外逐边沿计算，检查边界前一 tick、边界 tick 和后一 tick。
管理正常周期为 2000 ps，PCIe 为 4000 ps，DDR CK 引用 949 ps。

无竞争、单播子请求≤64 B、源与上游持续就绪、保护和目标就绪、正常时钟
稳定且目标服务≤250 ns 时，端到端参考目标为 1 µs。多片父请求的总时间
按完整分片流另测。八跳距离包络的 PCIe 64 B 读写参考值为
369.592 ns，含源 CDC 30 ns、Mesh 与 NI 74 ns、DDR CDC 15.592 ns 和服务
250 ns。表中的零至八跳是统一距离包络，实际来源的可达距离由固定坐标决定。

25 MHz 核心的同一八跳包络为 2.96 µs，仅 Mesh 与 NI 已超过正常工作点目标。
该值用于低速时钟敏感性分析。当前固件在管理时钟切换和 PLL 锁定之后释放
NoC，源端准入仍遵循真实 CRC 状态，启动流程由时钟规格拥有。

### 7.3 带宽与驻留约束

1 GHz 下每方向原始线量上界为 64 GB/s，完整 64 B 数据包占两拍，故单链路
单方向有效载荷上界为 32 GB/s。四个 Memory Tile 本地边界合计 128 GB/s。
当前八通道 LPDDR5-8433 引脚理想值为 134.928 GB/s，报头占用使 NoC 边界先
形成上限。请求头、完成、控制、信用停顿和热点使实际值继续降低。

双向各有独立链路，读请求和写完成占据相反方向，读写混合须联立计算。
多播每条实际树边占线量，复制本身不能提高单输入的服务速率。
PCIe 的完整包源 CDC 在 250 MHz 下单方向最多传 16 GB/s 有效载荷，管理源
500 MHz 时为 32 GB/s，均按每拍一个最多 64 B 数据包推算。
槽位敏感性另按 `槽数×64 B/固定往返驻留时间` 计算。代入相位包络仅构成
参考驻留示例，实际吞吐上界需要实际平均驻留时间或已证明的最小驻留约束。

HDMA 的 64 个 NoC 子请求槽共享两个方向。当前 HDMA 默认 devChunk=64 B，
每来源 16 个父事务使当前生产者最多维持 16 个此类子请求。
预算同时列出两种驻留示例，G2 验证父请求分段并行度及实际使用的槽数。
目标 250 ns 是夹具条件，原生 FR-FCFS、行冲突和刷新场景各自测量。
