## 1. 范围与实施顺序

本次实现对象为 SK hynix H58G66CK8BX147。保留适用于该 SKU 的全部已公开数字行为：命令、MR、状态、等待、训练程序和失败路径。电压、眼图、SI 和模拟校准计算排除；训练的物理反馈由可控替身提供，真实 RISC-V 固件仍须执行编程和判定。

明确未公开的厂商私有语义列为不可验证，不编造返回值。**已公开编码但缺少型号取值的能力位不能作为私有行为直接排除**；默认关闭不等于不支持。

按 G0→G1→G2→G3→G4 独立交付，允许先用临时 timing 连接适配器，后续替换真实 NoC；此顺序覆盖旧 Goal 的相关先后约束。真实 NoC、PCIe 链路和整个 M5/M7 不因此关闭。

分别报告器件规格一致性、GW100 控制器性能和实物校准。没有实物或厂商模型时，只能报告规格与独立参考的一致性，不能宣称实物误差。

## 2. 已固定的器件与工作点

| 项 | 决定与依据 |
|---|---|
| 器件 | H58G66CK8BX147，Rev 1.0，2024-04；SK1 p.2–5 |
| 组织 | 每封装两条 x16 通道，每通道两个 16 Gb rank；SK1 p.3、p.5 |
| GW100 配置 | 四封装、四 Memory Tile、八通道，共 32 GiB（由组织推算） |
| 通道交织 | 沿用 spec-address-map §3.2 的 256 B、DPA[10:8] |
| 启动点 | CK 25 MHz，使用手册复位默认模式；25 MHz 是 GW100 选择，不是器件固有频率 |
| 正常点 | 标称 8533 档；CK 1066.5 MHz、WCK:CK=4:1、BG、BL32 |
| 实际数据率 | 1066.5 MHz×4×2=8532 Mb/s/pin；x16 通道 17.064 GB/s，八通道 136.512 GB/s（引脚理想上限，推算） |
| 延迟 | x16、Read Link ECC/DBI/Data Copy 关闭时 RL Set 0；WL Set A；最高档 RL=23 CK、WL=12 CK（SK1 p.269、p.273） |
| 电源与环境 | 产品固件显式控制低功耗，不做运行中自动调频；默认 25°C，环境输入驱动数字温度报告与刷新要求 |

1066.5 MHz 同时考虑延迟表和 CK/WCK 周期下限（SK1 p.586、p.591），不能直接使用 8533÷8 的 1066.625 MHz。CK 周期为 2,000,000/2133 ps，WCK 周期为 500,000/2133 ps（推算）；必须累积精确相位后量化事件边沿，不能累加四舍五入的单周期。

器件仍须支持全部适用合法模式转换；配置须通过 MRW、FSP 或复位生效，Python 不能预置训练成功。存储可以稀疏分配，但物理容量、译码、资源和时序不变。

## 3. 来源与共享参数

已核实定义的单一真源为 h58g66ck8bx147.json 草案，由 tools/dram_spec.py 生成固件 C、模型 C++、配置 Python 定义。源路径相对仓库根目录；生成物尚未接入产品配置或固件。

| 参数 | 正常基线取值 |
|---|---|
| tRCD | ACT-2→WRITE：max(8 ns, 2 CK)；ACT-2→READ/Masked Write：max(18 ns, 2 CK) |
| tRPab / tRPpb | max(21 ns, 2 CK) / max(18 ns, 2 CK)，不得合并 |
| tRASmin / tRC | max(42 ns, 3 CK)；tRC=tRAS+相应 tRP |
| tWR | max(34 ns, 3 CK)；完整命令约束还需考虑数据结束锚点 |
| tRRD / tFAW | max(3.75 ns, 2 CK) / 15 ns |
| tRBTP | CKR=4:1 时 max(7.5 ns, 2 CK)−2 CK |
| tWTR_S / tWTR_L | max(6.25 ns, 4 CK) / max(12 ns, 4 CK) |
| tPPD | 2 CK |
| 刷新 | 16 Gb、BG/16B、Enhanced DVFSC 关闭：tRFCab 280 ns、tRFCpb 140 ns、tpbR2pbR 90 ns、tpbR2act 7.5 ns |

核心来源为 **SK1 p.532 Table 396**，条件为 x16、BG、DVFSC/Enhanced DVFSC/Write Link ECC 关闭。p.527–530 是 LPDDR5 表，不能混用。刷新来自 p.295 Table 240：1x 窗口 32 ms、8192 次、表列平均间隔 3.906 µs，Tcase≤85°C；还须实现 MR4、温度和推迟规则。一次 tRFCab 不是最坏服务时间。

真源目前只包含正常基线和部分 MR 默认掩码，**不是完整时序表或复位映像**。其他模式、训练、FSP、低功耗、命令间与 rank 间约束仍须展开。MR 默认值只能应用于对应 mask 内，其他位不能补零。

~~~sh
.venv/bin/python tools/dram_spec.py --generate
.venv/bin/python tools/dram_spec.py --check
.venv/bin/python tools/dram_spec.py --check --require-g0
.venv/bin/python -m unittest discover -s tools -p 'dram_spec_test.py' -v
~~~

普通检查验证原件摘要和生成一致性；严格检查在资料或审查未齐时返回 2。普通检查成功不代表 G0 通过。头文件以 GW100_REQUIRE_DRAM_G0 使用时拒绝未通过的档案；未知能力不生成可误用的数值。本工具不是 G4 独立时序检查器或性能参考。

SK1 原件见 [来源说明](../../../../reference/sk-hynix/2024-uttc-h58g66ck8bx147/README.md)，检索记录见 sources.md 草案，覆盖清单见 coverage.md 草案。

## 4. 资料阻塞和旧缺口

| 项 | 现有证据与影响 | 解除条件 |
|---|---|---|
| B1：只读能力 | MR0/1/19/21/24/26/41/43/57/75 中部分型号值未知；影响训练、可选功能和错误计数 | 同 SKU/修订的补充规格、厂家确认或可追溯的逐通道逐 rank MRR 读数 |
| B2：刷新管理 | MR27 的 RFM required、RAAIMT、RAAMULT 由厂商烧录，SK1 p.170 未列型号值；影响命令与性能 | 型号烧录值及修订；不能填零或借用其他型号 |
| B3：8B | p.4 说低速支持 8B；p.16/p.29 的 LPDDR5X 表仅列 BG、16B | 型号勘误/补充规格；不能套用 LPDDR5 表 |
| G0 实施待办 | 逐位域覆盖、全量时序表、软件接口位域和交叉审查未完成 | 继续规格细化和审查；这些不能全部归因于厂商缺资料 |

旧 v0.0 的资料缺口 G1–G4 与本次实施关口不同：旧 G1 的正常基线已有 SK1 原文，但完整模式时序未收敛；旧 G2 的 32 GiB 组织已由 p.5 落实；旧 G3 的训练接口/固件仍未完成；旧 G4 的 8533 默认固定为 BG/4:1/BL32，低速完整覆盖仍受 B3 约束。

原 Micron Y52Q/Y4BM 和 gem5 LPDDR5 参数仅作此前候选调研，不作为 SK 参数。查询其他厂商不表示已更换器件；替换前须重新核对组织、能力和适用条件。

## 6. 模型、控制器和固件契约

器件保存两通道、每通道双 rank 的数据、MR、状态，约束 CA/DQ/WCK/RESET/ZQ 资源，覆盖双阶段命令、WCK 同步、分段 burst、rank 切换和数据可见时刻。复用 gem5 事件、端口、时钟与存储；MemCtrl 只作部分读写的辅助对照。

GW100 控制器参数是设计选择：每通道 64 读槽、64 写槽，每槽 64 B，计入返回反压和写数据；初始化命令/结果各 16 项；CDC FIFO 各八项、指针同步两级；请求和响应流水各两级。FR-FCFS 允许年轻请求最多越过老请求八次，读写批次最多 16 burst，开放行自适应且刷新有截止。部分写为受保护原生 burst RMW，器件另实现 Masked Write；同地址有序，fence 等此前相关写入可见。后续实验记录资源成本。

连接适配器传递由硬件入口确定的来源身份、事务编号和复位代次；不能依赖软件可伪造标签或跨 System 可能重号的 RequestorID。正常管理 CPU、HDMA、BAR2 数据访问全部 timing；调试/checkpoint 不代替传输或初始化。未就绪请求明确报错，队列满反压，已接收请求完成一次或明确错误；迟到响应不能修改新代次。排空后 checkpoint 保存数据、MR 及必要时序状态。适配器与 DRAM 耗时分别报告。

fw_main 入口为 STAGE=4、FW_READY=0。建立计时/看门狗/事件服务→控制访问路径→DDR PLL 锁定→低速释放与 MR/FSP 编程→初始化/训练/切频→八通道双 rank 就绪→正常 timing 自检→保护表锁定→HDMA/HDI→检查电源/FLR/错误后 FW_READY=1。初始化是仿真中 RISC-V 固件执行的工作，构建只编译程序。

等待必须有规格与有限步骤推导的上界，期间喂狗和服务事件；失败记录通道/rank/阶段/原因，INIT 错误、STAGE=0xF，保持不就绪。冷/热/设备完全复位重新初始化；FLR 保留 DRAM 配置和数据，初始化中确认 FLR 后继续原流程，不能提前就绪。初始化中 D3hot 保持不就绪，完成有界 DRAM 初始化后自刷新，D0 后继续其余步骤；正常 D3/D0 排空并真实进入/退出自刷新。

精确配置使用 timing/O3 Host 及独立 timing 设备域，正常与测试固件共用初始化。旧 atomic 配置与匹配固件单独命名保留，不计新模型验收。原 17 个裸机测试、10 个 GTest 程序不得削弱；新增测试按能力分类，未分类使矩阵检查失败。

G4 独立 Python 检查器不复用 C++ 调度/合法性代码；覆盖全部数字行为、时序边界前/当时/后、数据边界/部分写/并发、温度/刷新/低功耗、各阶段失败/复位/FLR/D3、队列反压、迟到响应与 checkpoint。合法时序违规为零、数据正确，确定性事件误差≤一次 tick，代表性延迟/吞吐对独立参考≤±5%。控制器入口、适配器、PCIe、Host 分别计量；HDMA COPY 不作为唯一峰值证明。记录版本、时钟、模式、队列、调度、种子、窗口；未实物校准和真实 NoC 关口继续保留。

## 7. 软件接口审查草稿

既有 Tile 窗口和权限由 spec-address-map §4、§5 拥有。公共块、两通道块和四项保护表的偏移与宽度已在真源 mmio 中分配并生成共享常量；尚无运行实现。

公共块含版本、拓扑、能力、复位代次、错误快照、保护锁、计数器冻结；通道块含时钟选择/确认/实际频率、有限命令与结果队列、训练阶段、错误、数字 PHY 反馈编程。控制器错误与真实 MRR 数据必须区分，未定义 MRR 不得合成零值。保护表遵守四项、4 KiB 对齐、管理 CPU 唯一编程、四 Tile 一致回读后锁定；FLR 不解锁。

接口位域、命令格式、反馈锁存、结果确认、FIFO 满行为、计数器宽度/冻结和复位收尾尚未完成审查；review.interface_complete 保持 false。不能因为已经生成寄存器偏移就放行 G0。
