# 通用 LPDDR5-8433 性能预设

本文是 spec-dram 的通用性能模型附录，记录参数预设及八通道集成验证。
本轮交付采用 gem5 原生 LPDDR5 时序框架，工作点为用户指定的
8433 MT/s，类名为 LPDDR5_8433_1x16_BG_BL32。

## 参数依据

参数定义由 gem5-ext/src/memory/LPDDR5.py 拥有，继承
gem5/src/mem/DRAMInterface.py 的 LPDDR5_5500_1x16_BG_BL32。
配置通过 m5.objects 导入，控制器由继承的 controller() 创建。

组织沿用基类的 x16、每 rank 一个器件、每通道一个 rank、8 Gb 容量、
四 bank group、每组四 bank、2 KiB 行缓冲和 BL32。基类同时提供
有限读写队列、页面策略、双阶段 ACT 和数据时钟同步的时序抽象。

CK 与 WCK 的比例沿用基类，WCK:CK=4:1，每 CK 对应八个数据传输拍。
CK 周期按 8000/8433 ns 推算。BL32 包含两个 BL16 子突发，每段占
两个 CK，中间间隔两个 CK，完整跨度为六个 CK。跨 bank group 的
可交织间隔为两个 CK，同 bank group 间隔为八个 CK。

下列量按目标 CK 周期推算。

| 参数 | 推算规则 |
|---|---|
| tCK | 一个 CK |
| tBURST | 六个 CK |
| tBURST_MIN | 两个 CK |
| tBURST_MAX、tCCD_L、tAAD | 八个 CK |
| tCS、tPPD | 两个 CK |
| tRTW | 一个 CK，沿用基类 RL=WL 的调度假设 |
| tRTP | max(7.5 ns, 两个 CK)−两个 CK |

tRCD、tRP、tRAS、tWR、tRRD、tFAW、刷新和低功耗退出等纳秒约束
沿用基类，tCL 也沿用基类的绝对时间。tCWL 继承通用接口默认的
Self.tCL。提高传输速率时保持这些阵列访问延迟，是本预设的建模选择。
这些选择可用于通用架构性能比较，型号专属参数另由具体器件档案定义。

时序参数由 gem5 转换到全局 tick。该预设沿用原生 DRAMInterface
的事件量化方式，结果同时记录量化后的参数和实际数据率。

## 验证入口

配置位于 gem5-ext/configs/feasibility/lpddr5_8433.py，使用真实
MemCtrl 和 timing 请求。latency 场景将控制器设为 open-page，
在第一次刷新之前测量预热后的单行读取，期望控制器内部服务时间为
tCL+tBURST。其他场景保留类默认页面策略和刷新，产生读、写及混合流量。
各场景都限制在途请求数。

引脚峰值按 x16 宽度和目标数据率推算，单通道为 16.866 GB/s。
该值用于核对参数和 gem5 peakBW 统计。流量实测带宽还包含排队、
刷新和行切换开销。控制器响应包含其前后端流水和测试互连延迟。

本附录的交付关口为模型注册、实例化、timing 流量及上述手算对照。
前期型号资料档案中的 G0 审计对应型号专属数字模型。

## 验证结果

2026-11-06 在 gem5 f5c5a6e390f55dd5984977815bf9d0bd05da6945 上运行，
仿真 tick 为 1 ps，测试互连时钟为 2 GHz，在途请求上限为 64，
随机种子为 gem5 默认值 5489。控制器流水使用上游默认参数。
latency 预热后生成 2 µs 流量，其余模式生成 100 µs 流量，
统计窗口包含末尾排空。

| 场景 | 结果 |
|---|---|
| 行命中服务时间 | 28.972 ns，手算 28.971925 ns，误差小于一次 tick |
| 峰值参数核对 | 16868.00 MB/s，手算 16866.00 MB/s，偏差约 0.012% |
| 读流量 | 15773.74 MB/s |
| 写流量 | 15556.80 MB/s |
| 读写混合流量 | 11810.51 MB/s |
| 原有裸机回归 | timing 与 atomic 共 34/34 通过 |
| 原有 GTest | 10 个程序、94/94 用例通过 |

上述流量数值由 DRAM 侧统计给出。行命中服务时间从控制器入队计算到
数据就绪，响应路径还包括控制器流水与测试互连。
1 ps 量化后的 tCK 为 949 ps，对应等效数据率约 8429.926 MT/s，
各时序参数分别由精确推算值转换到 tick。

## 八通道集成

2026-11-07 的系统使用四个 Memory Tile，每 Tile 两条 x16 通道。
系统覆盖参数由 spec-src/dram/gw100-memory.json 拥有，生成固件、C++、
Python 定义。器件类的独立默认值仍用于上面的预设验证。
正式系统为每通道两个 16 Gb rank，设备容量合计 32 GiB。
常温刷新覆盖为 tRFC 280 ns、tXS 287.5 ns、tREFI 3.9 µs。

| 组成 | 实现位置 | 责任 |
|---|---|---|
| 规格生成 | tools/memory_spec.py | 检查拓扑、容量、地址、时钟与寄存器的一致性 |
| 软件控制 | src/gw100/mem_tile/memory_control | 状态、保护表、锁定、错误快照和冻结计数器 |
| timing 传输 | src/gw100/mem_tile/memory_link、memory_ingress、memory_tile | 三个硬件来源、原始 DPA、CDC、有限槽位、RMW 和返回背压 |
| 设备系统 | configs/gw100/devices/memory.py | 八个原生控制器、32 GiB 稀疏后端、实际 CORE/DDR 时钟 |
| 固件 | firmware/fw/dram.c、fw.c | 训练反馈检查、数据自检、保护、FLR 和电源状态 |
| 原生接口 | patches/0004–0006 | 异步 PIO、媒体生命周期、稀疏 checkpoint 恢复 |

表中的模型路径相对于 gem5-ext。固件和工具路径相对于仓库根目录。
控制器采用共享规格的 64/64 读写槽、FR-FCFS、close_adaptive。
每侧控制器流水为两个量化 CK 周期。三条来源入口分别为管理 CPU、
HDMA、BAR2，每来源保持十六个事务槽直到上游接受响应。

## 当前验证记录

仿真采用 gem5 f5c5a6e390f55dd5984977815bf9d0bd05da6945 加本地原生补丁，
全局 tick 为 1 ps，种子为 5489。组件测试始终实例化完整八通道和
32 GiB，single 只约束流量来源通道。性能参数、队列和训练时延使用
gw100-memory 档案，故障矩阵只修改对应的反馈位。

| 项目 | 结果 |
|---|---|
| 共享规格 | 生成检查及 5/5 Python 用例通过 |
| 组件、时序、流量、checkpoint | 21/21 场景通过 |
| 固件故障矩阵与自检失败 | 64 项反馈故障、16 项逐 rank 自检、1 项原有开关兼容，共 81/81 通过 |
| 默认裸机矩阵 | timing/gw100 22 项与 atomic/gw100_compat 17 项，共 39/39 通过 |
| 能力分类 | 5 项 DRAM 测试按声明跳过 atomic 兼容配置 |
| O3 Host | boot_ok、dram_access、hdi_copy、dram_lifecycle、dram_boot_events，5/5 通过 |
| 单元测试 | 原有程序与新增 MemoryControl，共 11 个程序、103/103 用例通过 |
| 16 Gb 双 rank 控制器行命中 | DRAM 服务 28.972 ns，含两侧流水 32.768 ns，与独立期望相等 |
| DDR 请求 CDC | 测量相位为 1.366 ns，与两级同步的独立边沿计算相等 |
| 管理入口 64 B 行命中往返 | 58.000 ns，控制器占 32.768 ns，临时适配器占 25.232 ns |

行命中微基准在首次刷新前预热，并单独使用 open-page。
完整产品配置使用 close_adaptive，压力和保持测试包含原生刷新与 rank 切换。
上面的读写吞吐属于独立预设场景。八通道引脚带宽手算上限为
134.928 GB/s，临时核心交叉开关的原始上限为 32 GB/s，来源 CDC 还
计入包头和负载传输。系统 COPY 时间包含这些路径和 Host 软件。

每次运行保留 config.ini、stats.txt、原始日志。memory_verify.py 的
results.json 记录模型版本、源码与可执行文件指纹、种子、命令、测量窗口、退出码、墙钟耗时及独立期望，run_gw100.py 的
memory.json 记录实际时序、策略、训练参数、各来源计数与 Tile 状态。
CDC 和传输计数为逐拍累加量。DRAM、控制器与临时适配器的事务延迟
分别从命令 trace 的边界测量。

复现命令在仓库根目录执行。

```sh
make test TEST_JOBS=4
make memory-test TEST_JOBS=4
.venv/bin/python tools/gtest.py --jobs 8
make test HOSTS=o3 TESTS="boot_ok dram_access hdi_copy dram_lifecycle dram_boot_events"
```

本轮三个交付关口分别由共享定义检查、完整组件验证、真实固件闭环覆盖。
训练反馈采用控制器级抽象，校准 10 µs、训练 100 µs 为设计选择。
原生模式、WCK、电源状态及逐参数量化的适用范围登记于理想化 #25、#26。
排空后的恢复重建原生 rank 状态，测量窗口从重建完成后开始。
临时 NoC 和 PCIe 链路分别保留 #10b、#2a–2c 的集成关口。
