# 通用 LPDDR5-8433 性能预设

本文是 spec-dram 的通用性能模型附录，记录 2026-11-06 确认的实施范围。
本轮交付采用 gem5 原生 LPDDR5 时序框架，工作点为用户指定的
8433 MT/s，类名为 LPDDR5_8433_1x16_BG_BL32。

## 参数依据

参数定义由 gem5-ext/src/memory/LPDDR5.py 拥有，继承
gem5/src/mem/DRAMInterface.py 的 LPDDR5_5500_1x16_BG_BL32。
配置通过 m5.objects 导入，控制器由继承的 controller() 创建。

组织沿用基类的 x16、每 rank 一个器件、每通道一个 rank、8 Gb 容量、
四 bank group、每组四 bank、2 KiB 行缓冲和 BL32。基类同时提供
有限读写队列、页面策略、双阶段 ACT 和数据时钟同步的时序抽象。

CK 与 WCK 的比例沿用基类，WCK:CK=4:1，每 CK 对应八个数据传输拍。
CK 周期按 8000/8433 ns 推算。BL32 包含两个 BL16 子突发，每段占
两个 CK，中间间隔两个 CK，完整跨度为六个 CK。跨 bank group 的
可交织间隔为两个 CK，同 bank group 间隔为八个 CK。

下列量按目标 CK 周期推算。

| 参数 | 推算规则 |
|---|---|
| tCK | 一个 CK |
| tBURST | 六个 CK |
| tBURST_MIN | 两个 CK |
| tBURST_MAX、tCCD_L、tAAD | 八个 CK |
| tCS、tPPD | 两个 CK |
| tRTW | 一个 CK，沿用基类 RL=WL 的调度假设 |
| tRTP | max(7.5 ns, 两个 CK)−两个 CK |

tRCD、tRP、tRAS、tWR、tRRD、tFAW、刷新和低功耗退出等纳秒约束
沿用基类，tCL 也沿用基类的绝对时间。tCWL 继承通用接口默认的
Self.tCL。提高传输速率时保持这些阵列访问延迟，是本预设的建模选择。
这些选择可用于通用架构性能比较，型号专属参数另由具体器件档案定义。

时序参数由 gem5 转换到全局 tick。该预设沿用原生 DRAMInterface
的事件量化方式，结果同时记录量化后的参数和实际数据率。

## 验证入口

配置位于 gem5-ext/configs/feasibility/lpddr5_8433.py，使用真实
MemCtrl 和 timing 请求。latency 场景将控制器设为 open-page，
在第一次刷新之前测量预热后的单行读取，期望控制器内部服务时间为
tCL+tBURST。其他场景保留类默认页面策略和刷新，产生读、写及混合流量。
各场景都限制在途请求数。

引脚峰值按 x16 宽度和目标数据率推算，单通道为 16.866 GB/s。
该值用于核对参数和 gem5 peakBW 统计。流量实测带宽还包含排队、
刷新和行切换开销。控制器响应包含其前后端流水和测试互连延迟。

本附录的交付关口为模型注册、实例化、timing 流量及上述手算对照。
前期型号资料档案中的 G0 审计对应型号专属数字模型。

## 验证结果

2026-11-06 在 gem5 f5c5a6e390f55dd5984977815bf9d0bd05da6945 上运行，
仿真 tick 为 1 ps，测试互连时钟为 2 GHz，在途请求上限为 64，
随机种子为 gem5 默认值 5489。控制器流水使用上游默认参数。
latency 预热后生成 2 µs 流量，其余模式生成 100 µs 流量，
统计窗口包含末尾排空。

| 场景 | 结果 |
|---|---|
| 行命中服务时间 | 28.972 ns，手算 28.971925 ns，误差小于一次 tick |
| 峰值参数核对 | 16868.00 MB/s，手算 16866.00 MB/s，偏差约 0.012% |
| 读流量 | 15773.74 MB/s |
| 写流量 | 15556.80 MB/s |
| 读写混合流量 | 11810.51 MB/s |
| 原有裸机回归 | timing 与 atomic 共 34/34 通过 |
| 原有 GTest | 10 个程序、94/94 用例通过 |

上述流量数值由 DRAM 侧统计给出。行命中服务时间从控制器入队计算到
数据就绪，响应路径还包括控制器流水与测试互连。
1 ps 量化后的 tCK 为 949 ps，对应等效数据率约 8429.926 MT/s，
各时序参数分别由精确推算值转换到 tick。
