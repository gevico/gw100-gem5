## 一句话

编译器负责空间映射和粗粒度排序，硬件按"数据是否就绪"触发张量级指令。论文称之为"编排式数据流"，在硬件复杂度和软件控制之间取了个折中。

## 架构要点

**设计原则**（p.3）
- 基本不用多级 cache：每个 TPB 有自己的高带宽本地存储；TPB 与共享 SRAM 之间、共享 SRAM 与 DDR 之间，都由可编程 DMA 显式搬运。
- 指令定义在张量粒度：操作数直接从存储流入、结果直接流回存储，没有寄存器堆，也没有显式的 load/store。
- 集中派发：经 ICB 把指令广播给多个处理单元。同一个功能单元内的指令按派发顺序执行，不同单元之间可以乱序完成，依赖关系由软件负责同步。

**TPB 内部**（p.6–8）
- HBSM 既是数据存储，也是各功能单元之间的通信枢纽：生产方写入约定好的地址区间，再通过同步计数器通知消费方，不需要专用数据通路。
- 一次访存赢得仲裁后即视为全局可见，同步动作就挂在这次访存上。
- 功能单元：
  - TCU：矩阵运算；
  - CVU：可配置的向量流水线，可以一次流过完成 softmax；
  - DTDU：执行 TPB 指令的 DMA，负责搬运、转置、填充；
  - GSDU：由 cluster CPU 控制的 gather/scatter DMA，处理不规则搬运；
  - CSU：遇到需要 CPU 处理的指令时，向 cluster CPU 发中断；
  - SU：管理同步计数器。
- 张量地址生成器 TWU：多层嵌套循环，每层配置初值、步长、终值，可以用外层步长在两块缓冲区之间切换，实现双缓冲（p.7）。
- 同步计数器的语义（p.7）："更新"把计数器加一；"监视"给出期望值，计数器达到或超过期望值才放行，否则请求方暂停。

**软件**（p.8–9）
- 时空调度器：把大张量切成 mini-tensor，空间上分配到多个 TPB，时间上分阶段流水执行。
- 图编译器：做算子融合、布局变换和动态内存分配。
- 后端编译器：C 扩展编译器，生成调用张量计算、数据搬运、同步等硬件能力的内建指令。
- NPU 固件跑在 CCB 的 RISC-V 上，**在运行时即时编译 TPB 指令**，现场计算张量形状和地址。

## 存疑与待核对

- 1280 TOPS 的计算口径（精度、是否计入稀疏）论文没有说明。按 TCU 规模推算，INT8 稠密算力远达不到这个数字。
- 与 Thor-U 的对比说是"同功耗"，但没有给出具体功耗数值。
- Mesh 和 DRB 的拓扑细节、路由方式、流控方式都没有披露。
